# FIDO2 — plan 1 (phases 1 à 3) : jusqu'au second facteur utilisable

> **Pour les agents exécutants :** SOUS-COMPÉTENCE REQUISE — utiliser
> `superpowers:subagent-driven-development` (recommandé) ou
> `superpowers:executing-plans` pour exécuter tâche par tâche. Les étapes sont
> en cases à cocher (`- [ ]`).

**But :** rendre la carte utilisable comme second facteur U2F sur GitHub, Google
et GitLab, en posant le transport CTAP-HID et l'encodeur CBOR sur lesquels les
passkeys s'appuieront ensuite.

**Architecture :** on reproduit la stratification éprouvée du CCID/OpenPGP —
transport impur (`mode_fido.c`), trames pures et testées (`ctaphid.c`, `cbor.c`),
dispatch, crypto réutilisée. Les deux modules purs sont exactement ceux qui
lisent des octets fournis par l'hôte.

**Pile :** ESP-IDF 5.5.2, TinyUSB 0.21.0~1 (brut, pas le wrapper), mbedtls
(ECDSA secp256r1, SHA-256, HMAC), harnais de tests hôte CMake.

**Spec :** [`docs/superpowers/specs/2026-08-17-fido2-webauthn-design.md`](../specs/2026-08-17-fido2-webauthn-design.md)

## Contraintes globales

Elles s'appliquent implicitement à **chaque** tâche.

- **`usb_mode_set` et `sec_gate_console_confirm` n'apparaissent que dans**
  `usb/usb_mode.{c,h}`, `console/console.c`, `security/sec_gate.{c,h}` —
  **commentaires compris**. C'est un grep (`scripts/fast.sh`, garde-fou 4), et
  quatre implémenteurs s'y sont déjà fait prendre.
- **GPIO24, GPIO25, GPIO35 ne s'affectent jamais** hors d'un en-tête de carte.
- **Jamais de deep-sleep permanent.**
- **Seule de la logique pure entre dans `test/`** — aucun appel ESP-IDF, sinon
  ça ne compile pas sur l'hôte.
- **Tous les commentaires en français.**
- **TDD obligatoire** pour toute logique pure : test d'abord, rouge constaté,
  puis vert, puis **mutation transitoire pour prouver que le test mord**.
  Rapporter le rouge ET le vert. Si une mutation attendue rouge reste verte,
  **le dire** — c'est un trou de couverture, pas un test à ajuster.
- **Un harnais de mutation doit vérifier que la compilation a réussi** avant de
  conclure. Sans ça un échec de build devient un faux « ne mord pas » : l'erreur
  a été commise dans ce projet le 2026-08-17, elle est documentée dans `b5284bb`.
- **`./scripts/check.sh --fast` vert à la fin de chaque tâche**, vu de ses
  propres yeux. Jamais en tâche de fond : une tâche de fond notifie le
  coordinateur, pas l'implémenteur.
- **Ne jamais élargir le glob du port série à `/dev/ttyACM*`** — `/dev/ttyACM0`
  est le clavier KaSe V2 Debug de la propriétaire. Le seul port autorisé est
  `/dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_30:ED:A0:E0:BC:5F-if00`,
  et la puce se confirme par `chip_id` (`MAC: 30:ed:a0:e0:bc:5f`) avant tout flash.

## Trois écarts assumés par rapport à la spec

**1. Aucun eFuse n'est grillé dans ce plan.** La spec prévoit une clé maîtresse
en eFuse protégé en lecture ; **griller un eFuse est irréversible** et la
propriétaire ne l'a pas autorisé. Ce plan utilise donc la clé en NVS sur **les
trois cartes**, avec un HMAC logiciel. Le passage à l'eFuse est un travail
séparé, à lui demander explicitement.

**2. Le décodeur CBOR est reporté au plan 2.** `authenticatorGetInfo` n'a aucun
paramètre de requête : seul l'encodeur est nécessaire ici, et U2F n'utilise pas
CBOR du tout. Écrire un décodeur sans consommateur, c'est écrire du code jamais
éprouvé. Il arrivera avec `makeCredential`, qui en a réellement besoin.

**3. U2F EXIGE un certificat d'attestation — la spec se trompe sur ce point.**
Elle tranche « attestation `none` », ce qui est valide pour CTAP2 mais **n'existe
pas en U2F** : la réponse à `U2F_REGISTER` contient obligatoirement un certificat
X.509. Un certificat auto-signé est ce que font les implémentations libres et ce
que les navigateurs acceptent. Il est donc généré une fois et committé (tâche 7).

```c
/* hid_dispatch.c — proprietaire unique des callbacks HID de TinyUSB.
 *
 * TinyUSB les resout par symbole global : deux modes HID ne peuvent donc pas
 * les definir chacun. Ce fichier les possede et route vers le mode installe.
 * Aucun mode installe -> reponses inertes, jamais de dereferencement nul. */
static const hid_handlers_t *s_h = NULL;

void hid_dispatch_set(const hid_handlers_t *h) { s_h = h; }

uint8_t const *tud_hid_descriptor_report_cb(uint8_t instance)
{
    (void)instance;
    return (s_h && s_h->report_desc) ? s_h->report_desc() : NULL;
}

uint16_t tud_hid_get_report_cb(uint8_t instance, uint8_t report_id,
                               hid_report_type_t report_type,
                               uint8_t *buffer, uint16_t reqlen)
{
    (void)instance;
    return (s_h && s_h->get_report)
         ? s_h->get_report(report_id, report_type, buffer, reqlen) : 0;
}

void tud_hid_set_report_cb(uint8_t instance, uint8_t report_id,
                           hid_report_type_t report_type,
                           uint8_t const *buffer, uint16_t bufsize)
{
    (void)instance;
    if (s_h && s_h->set_report) {
        s_h->set_report(report_id, report_type, buffer, bufsize);
    }
}
```

```c
#define CTAPHID_PKT_SIZE      64u
#define CTAPHID_MAX_PAYLOAD   7609u   /* 57 + 128*59 */
#define CTAPHID_CID_BROADCAST 0xFFFFFFFFu

/* commandes */
#define CTAPHID_CMD_PING   0x01u
#define CTAPHID_CMD_MSG    0x03u
#define CTAPHID_CMD_INIT   0x06u
#define CTAPHID_CMD_CBOR   0x10u
#define CTAPHID_CMD_CANCEL 0x11u
#define CTAPHID_CMD_ERROR  0x3Fu

/* erreurs */
#define CTAPHID_ERR_INVALID_CMD 0x01u
#define CTAPHID_ERR_INVALID_PAR 0x02u
#define CTAPHID_ERR_INVALID_LEN 0x03u
#define CTAPHID_ERR_INVALID_SEQ 0x04u
#define CTAPHID_ERR_CHANNEL_BUSY 0x06u
#define CTAPHID_ERR_INVALID_CHANNEL 0x0Bu
#define CTAPHID_ERR_OTHER 0x7Fu

typedef enum {
    CTAPHID_IN_PROGRESS = 0,   /* message incomplet, attendre la suite */
    CTAPHID_COMPLETE,          /* message complet dans out */
    CTAPHID_ERROR,             /* erreur : err_code et err_cid renseignes */
} ctaphid_result_t;

typedef struct {
    uint32_t cid;              /* canal du message en cours */
    uint8_t  cmd;
    uint16_t expected;         /* longueur annoncee */
    uint16_t got;              /* octets recus */
    uint8_t  next_seq;
    uint8_t  buf[CTAPHID_MAX_PAYLOAD];
} ctaphid_asm_t;

typedef struct {
    uint32_t cid; uint8_t cmd; uint16_t len; const uint8_t *data;
    uint8_t  err_code; uint32_t err_cid;
} ctaphid_msg_t;

void ctaphid_reset(ctaphid_asm_t *a);
ctaphid_result_t ctaphid_feed(ctaphid_asm_t *a, const uint8_t pkt[CTAPHID_PKT_SIZE],
                              ctaphid_msg_t *out);
uint32_t ctaphid_next_cid(uint32_t last_cid);   /* jamais 0, jamais BROADCAST */
```

```c
/* Un message court tient dans un seul paquet d'initialisation. */
static void test_single_packet_message(void)
{
    ctaphid_asm_t a; ctaphid_reset(&a);
    uint8_t p[64] = {0};
    p[0]=0x11; p[1]=0x22; p[2]=0x33; p[3]=0x44;   /* CID */
    p[4]=0x80u | CTAPHID_CMD_PING;
    p[5]=0x00; p[6]=0x03;                          /* BCNT = 3 */
    p[7]='a'; p[8]='b'; p[9]='c';
    ctaphid_msg_t m;
    TEST_ASSERT_EQ(ctaphid_feed(&a,p,&m), CTAPHID_COMPLETE, "un paquet suffit");
    TEST_ASSERT_EQ(m.cid, 0x11223344u, "le canal est conserve");
    TEST_ASSERT_EQ(m.cmd, CTAPHID_CMD_PING, "la commande est conservee");
    TEST_ASSERT_EQ(m.len, 3, "la longueur annoncee est respectee");
    TEST_ASSERT(memcmp(m.data, "abc", 3) == 0, "la charge utile est intacte");
}

/* Une longueur annoncee superieure au maximum doit etre refusee AVANT toute
 * ecriture dans le tampon : c'est le debordement classique contre un
 * authentificateur. */
static void test_oversized_length_is_refused(void)
{
    ctaphid_asm_t a; ctaphid_reset(&a);
    uint8_t p[64] = {0};
    p[0]=1; p[4]=0x80u|CTAPHID_CMD_PING;
    p[5]=0xFF; p[6]=0xFF;                          /* 65535 > 7609 */
    ctaphid_msg_t m;
    TEST_ASSERT_EQ(ctaphid_feed(&a,p,&m), CTAPHID_ERROR, "longueur aberrante refusee");
    TEST_ASSERT_EQ(m.err_code, CTAPHID_ERR_INVALID_LEN, "et signalee comme telle");
}

/* Un numero de sequence hors ordre invalide la transaction. Sans ce controle,
 * un hote pourrait reordonner la charge utile d'un message signe. */
static void test_out_of_order_sequence_is_refused(void)
{
    ctaphid_asm_t a; ctaphid_reset(&a);
    uint8_t init[64] = {0};
    init[0]=1; init[4]=0x80u|CTAPHID_CMD_PING; init[5]=0x01; init[6]=0x00; /* 256 */
    ctaphid_msg_t m;
    TEST_ASSERT_EQ(ctaphid_feed(&a,init,&m), CTAPHID_IN_PROGRESS, "message entame");
    uint8_t cont[64] = {0};
    cont[0]=1; cont[4]=0x01;                        /* SEQ 1 au lieu de 0 */
    TEST_ASSERT_EQ(ctaphid_feed(&a,cont,&m), CTAPHID_ERROR, "sequence hors ordre refusee");
    TEST_ASSERT_EQ(m.err_code, CTAPHID_ERR_INVALID_SEQ, "signalee INVALID_SEQ");
}

/* Un canal different pendant une transaction en cours est occupe, pas ignore :
 * sinon deux hotes se marcheraient dessus en silence. */
static void test_other_channel_during_transaction_is_busy(void)
{
    ctaphid_asm_t a; ctaphid_reset(&a);
    uint8_t init[64] = {0};
    init[0]=1; init[4]=0x80u|CTAPHID_CMD_PING; init[5]=0x01; init[6]=0x00;
    ctaphid_msg_t m;
    (void)ctaphid_feed(&a,init,&m);
    uint8_t other[64] = {0};
    other[0]=2; other[4]=0x80u|CTAPHID_CMD_PING; other[6]=0x01;
    TEST_ASSERT_EQ(ctaphid_feed(&a,other,&m), CTAPHID_ERROR, "autre canal refuse");
    TEST_ASSERT_EQ(m.err_code, CTAPHID_ERR_CHANNEL_BUSY, "signale CHANNEL_BUSY");
    TEST_ASSERT_EQ(m.err_cid, 2u, "l'erreur part sur LE canal fautif, pas sur le notre");
}

/* Le canal 0 est interdit par la specification, le canal de diffusion ne
 * s'alloue jamais. Trois valeurs comparees, pas une a elle-meme. */
static void test_cid_allocation_skips_reserved(void)
{
    TEST_ASSERT(ctaphid_next_cid(0) != 0, "0 n'est jamais alloue");
    TEST_ASSERT(ctaphid_next_cid(0) != CTAPHID_CID_BROADCAST, "diffusion jamais allouee");
    TEST_ASSERT(ctaphid_next_cid(CTAPHID_CID_BROADCAST - 1u) != CTAPHID_CID_BROADCAST,
                "on saute la diffusion en arrivant dessus");
    TEST_ASSERT(ctaphid_next_cid(5) != ctaphid_next_cid(6),
                "deux canaux successifs different");
}
```

```c
     * emettrait toujours 8 octets serait valide en CBOR mais REFUSE par les
     * clients CTAP2, qui exigent le canonique. */
    uint8_t b[16]; cbor_w_t w;
    cbor_w_init(&w,b,sizeof b); cbor_uint(&w,0);
    TEST_ASSERT_EQ(w.len,1,"0 tient sur un octet"); TEST_ASSERT_EQ(b[0],0x00,"0x00");

    cbor_w_init(&w,b,sizeof b); cbor_uint(&w,23);
    TEST_ASSERT_EQ(w.len,1,"23 est la derniere valeur immediate");
    TEST_ASSERT_EQ(b[0],0x17,"0x17");

    cbor_w_init(&w,b,sizeof b); cbor_uint(&w,24);
    TEST_ASSERT_EQ(w.len,2,"24 bascule sur un octet suivant");
    TEST_ASSERT_EQ(b[0],0x18,"0x18"); TEST_ASSERT_EQ(b[1],24,"24");

    cbor_w_init(&w,b,sizeof b); cbor_uint(&w,255);
    TEST_ASSERT_EQ(w.len,2,"255 tient encore sur un octet suivant");
    cbor_w_init(&w,b,sizeof b); cbor_uint(&w,256);
    TEST_ASSERT_EQ(w.len,3,"256 exige deux octets");
    TEST_ASSERT_EQ(b[0],0x19,"0x19");
}

/* Un debordement doit se SIGNALER, jamais s'ecrire hors du tampon ni se
 * tronquer en silence : un CBOR tronque est un CBOR valide mais faux. */
static void test_overflow_is_flagged_not_truncated(void)
{
    uint8_t b[2]; cbor_w_t w; cbor_w_init(&w,b,sizeof b);
    cbor_text(&w,"beaucoup trop long pour deux octets");
    TEST_ASSERT(w.overflow, "le debordement est signale");
    TEST_ASSERT(w.len <= sizeof b, "rien n'est ecrit au-dela du tampon");
}

/* Le canari : un octet juste apres le tampon ne doit jamais changer. */
static void test_no_write_past_the_buffer(void)
{
    uint8_t b[9]; b[8] = 0xA5;
    cbor_w_t w; cbor_w_init(&w,b,8);
    cbor_bytes(&w,(const uint8_t*)"0123456789012345",16);
    TEST_ASSERT_EQ(b[8],0xA5,"le canari est intact");
}
```

```c
/* LA SEPARATION DE DOMAINE. Sans les octets de prefixe 0x01/0x02,
 * l'authentificateur du credential SERAIT sa cle privee — et le publier dans
 * le credential ID reviendrait a publier la cle. Ce test est la seule chose

static void test_key_and_tag_are_different_derivations(void)

/* Un credential ID forge pour un AUTRE domaine doit etre rejete : c'est ce qui
```

### Tâche 7 : `u2f.c` — REGISTER, AUTHENTICATE, VERSION

**Fichiers :** créer `main/security/u2f.{c,h}`, `main/security/fido_attest.h`,
modifier `main/usb/mode_fido.c` (router `CTAPHID_MSG`).

- [ ] **Étape 1 : le certificat d'attestation**

U2F l'exige — la spec se trompe en tranchant « attestation none », qui n'existe
pas dans ce protocole.

```bash
openssl ecparam -genkey -name prime256v1 -out /tmp/attest.key
openssl req -new -x509 -key /tmp/attest.key -days 7300 -sha256 \
  -subj "/CN=Niphargus FIDO Attestation" -outform DER -out /tmp/attest.der
xxd -i /tmp/attest.der > main/security/fido_attest.h
```
Committer la clé privée d'attestation **dans le firmware** en le disant
explicitement en commentaire : elle est partagée par tous les exemplaires, elle
n'a **aucune valeur de secret**, et c'est précisément ce que l'attestation
« basic » signifie.

- [ ] **Étape 2 : `U2F_VERSION` d'abord** — INS `0x03`, réponse `"U2F_V2"` +
  `0x9000`. Le plus petit aller-retour possible, qui valide toute la chaîne
  (transport, APDU, réponse) avant d'y ajouter de la crypto.

- [ ] **Étape 3 : `U2F_REGISTER`** — INS `0x01`, données `challenge(32) ‖
  application(32)`. Réponse : `0x05 ‖ pubkey(65) ‖ len(1) ‖ keyhandle(32) ‖ cert ‖ sig`.
  La signature porte sur `0x00 ‖ application ‖ challenge ‖ keyhandle ‖ pubkey`.
  Appeler `sec_confirm_arm()` puis attendre l'autorisation ; rendre `0x6985`
  (conditions non satisfaites) tant qu'elle n'est pas venue — c'est ce que le
  protocole attend, et le navigateur réessaie.

- [ ] **Étape 4 : `U2F_AUTHENTICATE`** — INS `0x02`, `P1 = 0x07` (vérification
  seule, **sans** présence physique), `0x03` (avec présence). Réponse :
  `presence(1) ‖ compteur(4) ‖ signature`. Le compteur reste à **0** (décision de
  la spec).

- [ ] **Étape 5 : ce que l'écran peut dire, et ce qu'il ne peut pas**

La spec décrit un écran affichant **le domaine** auquel on s'authentifie, avec
assainissement du texte hôte. **Ce n'est pas réalisable en U2F**, et il ne faut
pas essayer : U2F ne transporte aucune chaîne de domaine, seulement un
*application parameter* qui est un **hachage de 32 octets**. Il n'y a rien à
afficher, et rien à assainir. L'affichage du domaine et son assainissement
appartiennent au plan 2, avec CTAP2 — qui, lui, transporte le `rp.id` en clair.

Ce que l'écran peut dire ici, et qui suffit : **quelle opération** est demandée.
Ajouter deux valeurs à `sec_op_t` (`main/security/sec_confirm.h`) :

```c
SEC_OP_FIDO_REGISTER,   /* U2F_REGISTER : creer une nouvelle cle */
SEC_OP_FIDO_AUTH,       /* U2F_AUTHENTICATE : prouver une cle existante */
```

et les libellés correspondants dans `screen_op_label()` (`screen_view.h`) et
`screen_op_short()` (`screen_layout.h`). **Le test
`test_op_short_fits_the_double_height_font` va contraindre les libellés courts à
dix caractères** — c'est exactement son rôle. `"ENREGISTRER"` fait onze
caractères et sera refusé ; `"NOUVELLE CLE"` aussi. Prévoir `"CREER CLE"` (9) et
`"AUTH FIDO"` (9), ou justifier d'autres choix. Mettre à jour aussi
`test_op_short_maps_each_operation`, qui compare les libellés **deux à deux** :
sept valeurs font vingt et une paires.
